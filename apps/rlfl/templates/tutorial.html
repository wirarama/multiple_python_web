1. Konsep federated learning

Federated learning (FL) melatih satu model bersama dari data yang tersebar di banyak pihak (klien) tanpa memindahkan data mentah. Tiap klien melatih model di datanya sendiri, lalu hanya mengirim bobot model ke server. Server menggabungkan bobot tsb menjadi model global dan mengirimkannya kembali. Satu siklus ini disebut ronde komunikasi.

FedAvg (McMahan dkk., 2017)

wt+1 = Σk∈St (nk / n) · wkt+1    dengan wkt+1 = hasil E epoch SGD lokal mulai dari wt

Tantangan utama: data non-IID

Data tiap klien tidak berdistribusi sama (non-IID). Di aplikasi ini, region sepi hanya melihat link dengan utilisasi rendah, sehingga model lokalnya tidak pernah belajar bagaimana delay melonjak saat link macet. FL menggabungkan pengetahuan region sepi dan region padat.

Variasi agregasi yang tersedia

  • FedProx: menambah term μ/2·||w − wt||² pada loss lokal agar model lokal tidak "melenceng" terlalu jauh pada data non-IID.
  • FedMedian dan Trimmed Mean: agregasi robust terhadap klien yang mengirim bobot ekstrem (mis. klien rusak / berbahaya).
  • Differential Privacy (DP): update klien di-clip lalu ditambah noise Gaussian — privasi meningkat, akurasi menurun (trade-off).
  • Fraksi klien & peluang gagal kirim: mensimulasikan partisipasi parsial dan straggler.

2. Skenario jaringan yang disimulasikan

Jaringan dibagi menjadi beberapa region, masing-masing dikelola satu klien (mis. controller SDN lokal / ISP regional). Setiap klien hanya bisa mengukur link di region-nya (link perbatasan diukur kedua region). Tujuan bersama: memilih jalur ber-delay minimum antar node mana pun di jaringan.

Delay "sebenarnya" sebuah link pada utilisasi ρ mengikuti model antrian (mirip M/M/1):

delay = delay_dasar + Q · (12 / bandwidth) · ρ / (1 − ρ) + loss · RTO   (Q = 8, RTO = 200 ms)

Model ML tidak diberi tahu rumus ini; ia harus mempelajarinya dari pengukuran (utilisasi, bandwidth, delay dasar, loss → delay). Jalur optimal (oracle) dihitung dengan Dijkstra pada delay sebenarnya di saat evaluasi (snapshot), sebagai acuan.

3. Simulator jaringan & region

  • Bangkitkan Topologi Acak: atur jumlah node, k tetangga terdekat, luas wilayah, jumlah klien, seed. Delay dasar link diturunkan dari jarak.
  • Bagi Ulang Region: mengelompokkan ulang node ke region dengan k-means posisi tanpa mengubah link.
  • Tambah node / link, ubah bandwidth, loss, dan bobot trafik (link populer = bobot > 1). Klik baris link untuk mengisi form.
  • Daftar node: pindahkan node ke region lain melalui dropdown. Seret node pada peta untuk mengubah posisi (jarak & delay dasar dihitung ulang).
  • Peta jaringan: warna node = region; setelah data dibangkitkan, warna link = utilisasi saat evaluasi (hijau sepi → merah macet).

Setiap perubahan topologi/klien otomatis mereset data trafik dan hasil lama.

5. Data trafik lokal (non-IID)

Untuk tiap jam t (sebanyak langkah waktu), tiap klien mengukur utilisasi dan delay pada link yang dapat ia amati. Data dibagi menjadi latih/uji. Jam evaluasi routing menentukan snapshot kondisi jaringan untuk membandingkan jalur. Tabel statistik dan histogram mini memperlihatkan rentang utilisasi yang dilihat tiap klien.

6. Mode 1 — Federated Learning prediksi delay link

  1. Standarisasi federated: klien hanya mengirim jumlah, jumlah dan jumlah kuadrat fitur (bukan data) untuk menghitung mean/std global.
  2. Tiap ronde: server memilih klien → klien melatih MLP numpy (atau regresi linear) selama E epoch → (opsional DP) → server mengagregasi.
  3. Model memprediksi delay seluruh link pada snapshot → Dijkstra pada delay prediksi → tabel next-hop → jalur.
  4. Pembanding: Lokal-saja (tiap klien melatih sendiri dengan jumlah epoch setara R×E), Terpusat (semua data digabung — batas atas), Oracle.

Target model adalah log(1 + delay) agar lonjakan delay saat macet tetap bisa dipelajari.

7. Mode 2 — Federated Reinforcement Learning (Q-Routing)

Tiap klien adalah agen Q-Routing (Boyan & Littman, 1994). Qx(d, y) = estimasi delay bila paket di node x menuju d diteruskan ke tetangga y.

Qx(d,y) ← Qx(d,y) + α [ c(x,y) + minz Qy(d,z) − Qx(d,y) ]

Agen hanya mengalami paket yang berasal dari region-nya, sehingga ia hanya mengenal sebagian state (node, tujuan). Tiap ronde server menggabungkan tabel-Q: rata-rata berbobot jumlah kunjungan (entri hanya dipengaruhi agen yang pernah mengalaminya) atau FedAvg biasa. Kebijakan routing = memilih tetangga dengan Q terkecil (greedy). Kegagalan (loop) menunjukkan agen belum mengenal rute tsb.

8. Membaca hasil

  • Akurasi: persentase prediksi delay dengan |error| ≤ toleransi × delay sebenarnya, pada data uji gabungan semua klien.
  • Akurasi data sendiri: model lokal sering tampak baik di datanya sendiri, tetapi buruk di data klien lain (efek non-IID).
  • MAE per beban: perhatikan kelompok utilisasi tinggi — di sinilah model lokal region sepi gagal.
  • Gap jalur: rata-rata (delay jalur model − delay jalur optimal) / delay optimal. Jalur optimal %: proporsi pasangan yang jalurnya sama persis dengan oracle.
  • Komunikasi: byte yang dikirim (parameter × 4 byte × klien) — biaya FL dibanding mengirim data mentah.
  • Log ronde: klien terpilih, klien gagal kirim, loss dan metrik global tiap ronde.

Grafik reward per episode menampilkan jumlah reward positif (hijau) dan negatif (merah) tiap episode. Di awal, eksplorasi tinggi (ε besar) sehingga paket sering berputar → hukuman loop/delay/timeout besar. Seiring ε turun dan Q terisi, total reward naik dan stabil. Klik sebuah episode untuk membukanya di pemutar langkah.

9c. Routing per langkah & reward

  • Pilih Kebijakan akhir (greedy, Q tertinggi), Jalur delay minimum (pembanding Dijkstra yang dinilai dengan fungsi reward yang sama), atau Episode pelatihan ke-n.
  • Tombol ⏮ ◀ ▶ ⏭ / Putar menelusuri langkah demi langkah. Pada peta: segmen hijau = reward langkah positif, merah = negatif; lingkaran magenta = posisi paket; garis putus-putus = pilihan tetangga berikutnya beserta nilai Q-nya (magenta = yang dipilih).
  • Kartu penjelasan menguraikan setiap komponen reward langkah tsb, total r, return kumulatif, serta perhitungan update Q dengan angka sebenarnya. Badge menunjukkan apakah aksi dipilih karena eksplorasi (acak) atau eksploitasi (Q tertinggi).
  • Grafik batang bertumpuk memperlihatkan komponen + (di atas nol) dan − (di bawah nol) per langkah dengan garis return kumulatif; tabel di bawahnya dapat diklik.
  • Diskusi: bila jalur agen berbeda dari jalur delay minimum padahal reward-nya lebih tinggi, fungsi reward (mis. penalti hop atau kongesti) “menarik” agen ke tujuan lain — contoh nyata pentingnya desain reward.

12. Ide praktikum

  1. IID vs non-IID: samakan intensitas semua klien (mis. 0.6) lalu bandingkan selisih global vs lokal dengan kondisi intensitas berbeda-beda.
  2. Jumlah ronde vs epoch lokal: ronde sedikit × epoch banyak vs sebaliknya — amati akurasi dan biaya komunikasi.
  3. FedAvg vs FedProx pada data sangat non-IID (intensitas 0.1 vs 1.0).
  4. Partisipasi parsial: fraksi klien 0.5 dan peluang gagal 0.3 — kurva menjadi bergerigi?
  5. Privasi: DP clip 1.0, noise 0.02 / 0.05 / 0.1 — buat grafik akurasi vs noise.
  6. MLP vs linear: mengapa model linear gagal memprediksi delay saat macet, dan apa dampaknya pada jalur?
  7. Desain reward (tab RL): set bobot kemajuan = 0, lalu bandingkan episode pertama tiba di target; naikkan hukuman kongesti menjadi 200 dan amati jalur agen menghindari link merah.
  8. Q-Routing: ubah Lokal (dest_locality) menjadi 0.9 — cakupan agen lokal menurun, manfaat federasi makin terlihat.
